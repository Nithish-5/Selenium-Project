# Automated Login Form Testing Using Selenium (Java)

A production-ready test automation framework using **Selenium WebDriver (Java)**, **TestNG**, and **Maven** designed to test the login functionality on [The Internet - Login Page](https://the-internet.herokuapp.com/login).

---

## 📌 Project Overview

This project automates functional and data-driven testing for authentication scenarios using the **Page Object Model (POM)** design pattern, explicit waits, robust assertions, and automated driver management.

### Implemented Test Cases
| # | Test Case | Description | Expected Result |
|---|---|---|---|
| **1** | **Valid Login** | Enter valid credentials (`tomsmith` / `SuperSecretPassword!`) | User successfully logs in, redirected to `/secure`, "Secure Area" header and success flash banner are displayed. |
| **2** | **Invalid Login** | Enter invalid credentials (`wrongusername` / `wrongpassword`) | Error message `"Your username is invalid!"` is displayed; user remains on login page. |
| **3** | **Empty Fields** | Submit login with empty username and password | Error message is displayed; user remains on login page. |
| **★** | **Bonus: Data-Driven Testing** | Read test combinations from `login_data.csv` (Valid, Invalid User, Invalid Pass, Empty fields) | Each dataset is executed dynamically via TestNG `@DataProvider` and assertions are validated per row. |

## 🛠️ Tools & Technologies

- **Language:** Java (JDK 17 or 11+)
- **Automation Tool:** Selenium WebDriver `4.20.0`
- **Testing Framework:** TestNG `7.9.0`
- **Build & Dependency Management:** Apache Maven
- **Driver Management:** WebDriverManager `5.8.0` / Selenium Manager
- **Design Pattern:** Page Object Model (POM)
- **Data Source:** Custom CSV Reader (`CsvReaderUtil`)

## 🚀 How to Run the Tests

### Option 1: Run All Tests via Maven CLI
Navigate to the project root directory and execute:
```bash
mvn clean test
```

### Option 2: Run in Headless Mode (e.g. CI/CD or Background)
```bash
mvn clean test -Dheadless=true
```

### Option 3: Run Specific Test Class
```bash
# Run only core test cases (Test Case 1, 2, 3)
mvn test -Dtest=LoginTest

# Run only bonus data-driven tests
mvn test -Dtest=DataDrivenLoginTest
```

### Option 4: Run from IDE

#### In **IntelliJ IDEA**:
1. Open IntelliJ IDEA -> `File` -> `Open...` -> Select `selenium-login-automation` folder.
2. Allow Maven to import dependencies automatically.
3. Right-click on `src/test/resources/testng.xml` -> Click **Run 'testng.xml'**.
4. Or right-click any test class in `src/test/java/com/automation/tests/` and select **Run**.

#### In **Eclipse IDE**:
1. `File` -> `Import...` -> `Existing Maven Projects` -> Select project folder.
2. Right-click `testng.xml` -> `Run As` -> `TestNG Suite`.

#### In **VS Code**:
1. Open the project folder in VS Code.
2. Install **Extension Pack for Java** and **Test Runner for Java**.
3. Use the Testing tab in the sidebar or run via integrated terminal (`mvn test`).

## 💡 Best Practices Implemented

1. **Page Object Model (POM):** Complete separation between web element locators, page interactions, and test assertions.
2. **Explicit Waits (`WebDriverWait`):** No hard-coded `Thread.sleep()` pauses; dynamic synchronization using `ExpectedConditions` ensures stability and speed.
3. **Automated Driver Management:** Leverages `WebDriverManager` to automatically download and configure the matching browser driver binary.
4. **Data-Driven Architecture:** Decoupled test logic from data sets using custom CSV parsing and TestNG `@DataProvider`.
5. **Clean Assertions:** Informative assertion messages with expected vs actual comparison to facilitate debugging.
